# Automated Retail Sales Forecasting with Apache Airflow

Airflow 3 pipeline that ingests daily sales, validates them, compares three forecasting models,
and publishes a 14-day forecast (total + per store) with a report and chart every day.

```
ingest -> validate -> evaluate -> forecast -> report
```

| Step | What it does |
|---|---|
| ingest | Appends the new day's sales to `data/raw/retail_sales.csv` (simulated source; swap in a DB/API) |
| validate | Hard-fails on duplicates, nulls, negative sales, gaps, incomplete days |
| evaluate | Rolling backtest (3 folds x 14 days) of **seasonal-naive baseline, Ridge, Random Forest**; ML model is used only if it beats the baseline by >= 5% WAPE |
| forecast | Refits the chosen model, recursive 14-day forecast for TOTAL and each of 5 stores; saves `data/forecasts/forecast_<date>.csv` and `models/retail_sales_model.joblib` |
| report | Markdown report + chart; **scores the previous forecast against actuals** (monitoring) and flags an alert if WAPE > 20% |

## Dataset
`data/raw/retail_sales.csv` - 20,080 rows: 5 stores x 4 categories x daily, 2024-01-01 to 2026-09-30.
Columns: `date, store, category, units_sold, sales, promo`. It is **synthetic** (trend, weekly and yearly seasonality,
promotions, holidays, noise), generated by `scripts/make_dataset.py`. To use real data (e.g. a Kaggle retail
dataset), produce a CSV with the same columns in `data/raw/`.

## Run it (Mac/Linux)
```bash
python3 -m venv .venv && source .venv/bin/activate
PYV=$(python -c "import sys; print(f'{sys.version_info.major}.{sys.version_info.minor}')")
pip install -r requirements.txt --constraint "https://raw.githubusercontent.com/apache/airflow/constraints-3.1.8/constraints-$PYV.txt"
```
1. **Without Airflow first:** `python scripts/retail_forecast.py --step all --as-of 2026-10-01`
2. **With Airflow** (set these in every new terminal):
```bash
export AIRFLOW_HOME=$PWD/.airflow AIRFLOW__CORE__LOAD_EXAMPLES=False AIRFLOW__CORE__DAGS_FOLDER=$PWD/dags
airflow db migrate
airflow dags test retail_sales_forecast 2026-10-01
airflow dags test retail_sales_forecast 2026-10-02     # also scores yesterday's forecast
airflow standalone                                      # UI: http://localhost:8080
```
3. Look in `data/reports/` for the report and chart. **Tests:** `pytest -q tests` (8 tests).

## Verified results (`sample_output/`)
Backtest WAPE: Random Forest 2.44%, Ridge 2.92%, seasonal-naive 5.05% -> Random Forest chosen.
The second run scored the first run's 1-day-ahead forecast at WAPE 6.96% (a single day, and a holiday).

## Viva points
* Baseline + rolling backtest: you can show the ML model is actually better, not just run.
* Lag features + recursive forecasting keep trend and weekly pattern; calendar (holiday, promo plan) is known in advance.
* No leakage: tested - changing the last day's value does not change that day's features.
* Airflow shows: scheduling, retries, task dependencies, Params (horizon, thresholds), logs, idempotent ingest.
* Limitations: synthetic data; promo plan assumed known; no uncertainty intervals; file-based storage.
